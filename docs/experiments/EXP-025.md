- 新規スクリプト `scripts/blender/build_kannai_ignition_scene.py`（関内スチルのレシピを無変更で継承: 磁器 lift 0.04、ブルーアワー光設計、関内ベースマップ。変更は点灯のアニメーションとカメラ滑走のみ）。
- 点灯順: 関内駅（JR）の実座標 **北緯 35.44306・東経 139.63722** を、コンバータと同一の変換（EPSG:6697→6677、錨点ランドマークタワー差し引き）で局所座標 **(553.0, -1281.3) m** に変換。各開口の重心（バウンディングボックス中心）との平面距離を実測し（実測域 9〜788m、中央値 287m）、**点灯フレーム = 距離に線形（等速度の波面、約 13.6 m/frame）** で割当。845 件すべて個別マテリアル＋個別キーフレーム（バンド化なし）で、点灯後は点きっぱなし。各開口の色・強度はスチルと同じ md5 パレット（ばらつきのみ、順序と集合は純粋にデータ）。点灯ランプは 3 フレーム。対応表は `output/blender/exp025-wave-grabs/ignition-order.json` に全数保存。
- カメラ: 街路スチルの軸 (322,-731)→(470,-822) を高さ 4m に下げ、同軸上を 72fr で 6m 滑走（歩行より遅いドリー、屋根より上には出ない）。24fps。
- レンダー: Mac（Blender 4.2.9、CPU）で 1280×720 / 32 samples、72fr 逐次、約 47 分（約 39 秒/frame）。成果物 `output/blender/exp025-kannai-wave-test.mp4`（3.0 秒）。フレームグラブは `output/blender/exp025-wave-grabs/frame_*.png`。

## CHECK（技術）
- 点灯実績（対応表より）: fr12 で 32 件、fr24 で 397 件、fr42 で 596 件、fr62 で 845 件全点灯 — 設計どおり等速度で波面が進んだ。
- エラーなし。全フレームで開口の浮き・チラつき・ポップなし（3fr ランプが効いている）。

## CHECK（クリエイティブ、Muse 目視 — グラブと mp4 で判定）
- **波は読める — ただし画角の外で大半が終わる。** fr45 では遠方〜中景の店舗列が灯り前景が暗いという明確な空間勾配があり、「一斉フェード」でも「ランダムな瞬き」でもないことが分かる。fr50 で前景の大面が灯り、波がカメラを通過する。順序（遠→近=駅側→こちら側）は無条件に読み取れる。
- **しかし定量的な問題が露出した: fr42 の時点で全開口の 71%（596/845）が点灯済みなのに、画面の街路はまだほぼ真っ暗である。** このカメラ（馬車道の北西端）から見える回廊は駅から約 460〜790m の帯にあり、波の行程の前半（駅南の結節=全ポリゴンの約 2/3 が集まる地区）は画角の外で燃え尽きる。可視の掃引は実質 fr46〜62 の約 0.7 秒に圧縮され、テスト尺の前半約 1.8 秒は「灯る前の街路」が続く。
- カメラは主役を持ち続けた: 暗い局面でも消失点の残照スリットと街路の構図が「待っている街」として成立し、全点灯後はスチルで確認した両側の灯りの列がそのまま画になる。6m の滑走は 3 秒尺では微細だが、方向は正しい。
- 副次的な発見: 32 samples では強いパレットバケットの灯りがアンバーではなく白〜クリームに飛ぶ（AgX 下の露出過多）。スチル（96 samples）より色が浅い。本編では上位バケットの強度抑制か色の深化が要る。

## ACT（判定と本編設計）
- **判定: 機構は合格、構図と尺が不合格（テストとして成功）。** 「点灯の集合も順序も実データ」という核は動画でも成立し、波の読みは実証された。敗因は演出ではなく幾何: 波の発生源（駅）と主役の回廊（馬車道）が離れており、単一の固定軸カメラでは行程の大半が見えない。
- 本編設計（この判定を受けた構成）: 尺 75〜90 秒・3 幕。(1) 第1幕（0〜15 秒）: 関内駅南の結節地区の街路レベル — 波の発生そのものを見せる（最も密な灯りが駅から広がる）。(2) 第2幕（15〜60 秒）: 馬車道の滑走 — 開始位置を南東へずらし（追補のカメラ課題と一致）、波が回廊を遠→近に掃引してカメラを追い越す。波速は等速度を維持し、尺で割る（約 55 秒で 788m）。カメラは屋根より上に出ない。(3) 第3幕（60〜90 秒）: 全点灯後にだけ低い空撮（文脈スチルの 39m 級）へ抜け、地区全体で閉じる。最後に総数 845 が題の答えとして出る。
- レンダー見積もり（要 GPU 実測）: 本テストの CPU 実績（1280×720/32 samples で 39 秒/frame）を 1920×1080/96 samples に換算すると約 3 分/frame 級で、90 秒=2160fr は約 110 時間 — CPU では不可能。EXP-022 で実証した Mac GPU（METAL）経路の実測（1080p/64 samples で約 1.8 分/frame 級）を関内シーンでベンチし直すことが本編着手の前提。尺を 60 秒に縮める案（1440fr）も併記する。
- 人間に必要な判断: なし（本編化の最終採用は従来どおり完成尺を見てから）。
