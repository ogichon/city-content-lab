# EXP-023 — ライブWeb路線の再試行・第1段: 夕景シルエット化の原因調査

## 対象の欠陥（EXP-021 / EXP-022 で2作品を止めた壁）
実Chromeのユーザースクショで2作品連続で観測された症状は、実は2つある。混同しないために分けて扱う。
- **症状A（シルエット化）**: 夕景設定のステージで、建物が磁器として照明されず、全棟が無照明の濃紺シルエットになる。EXP-022 では水位0.6（沈没対象がほぼ無い状態）でも全棟が暗い → 水の素材分岐は無関係で、夕景×建物の照明経路そのものが原因。
- **症状B（黒フレーム）**: 再生中に black 100% のフレームが反復する（EXP-022: 31s / 61s、ループの異なる位相で発生）。

## コード読解: 建物の色と照明はどう作られるか（src/viewer.ts、src/recipes.ts）
- 太陽と空は `ThreeView({ atmosphere: { date: new Date(time.iso) } })` + `plugin.addDefaultPhotorealScene()`（takram系の物理大気）。太陽位置はプリセットの絶対時刻だけで決まる。`scene.sun` は castShadow のみ上書き。
- 建物は 3D Tiles レイヤー。レイヤーレベルの model は `color: 白 / metalness: 0 / roughness: 1`（growth / standard モード）。viewer.ts のコメントどおり Navara 0.2.1 では metalness/roughness はモデル均一値が正で、**FeatureEvaluator が返す per-feature の metalness/roughness は効かない**。
- FeatureEvaluator の style コールバックが返す color / emissive / emissiveIntensity / opacity / show が特徴ごとの見えを決める。color は特徴の拡散色差し替えで、照明（PBR）自体は残る（後述の反証参照）。
- 失敗した2作品の style はどちらも **emissive = 0**:
  - EXP-021（growth 既定分岐）: `emissive: 0`（emissive を持つのは lift モードだけ: 白 × 0.15）。
  - EXP-022（porcelain 分岐）: MATERIALS.porcelain は emissive [0x000000, 0x000000] / intensity 0。
- 環境光は単一 ambient（色 0x93a7cc=青灰）のみ。プリセット強度は day 0 / **sunset 0.15** / night 0.6。
- EXP-016 のステージグレード3点（地形 lit:false / aerialPerspective transmittance:false / 雲 hazeDensityScale:0）は全て「地面」と「距離減光」への対策で、**建物に光を足すものは1つもない**。露出は stage で ×1.25 のみ。

## 実測（机上計算で確定）: プリセット時刻の太陽高度
NOAA 近似で東京（35.668, 139.778）・2026-11-05 の太陽高度を計算した。

| プリセット | 時刻 (JST) | 太陽高度 |
|---|---|---|
| day | 12:00 | **+38.2°** |
| （参考） | 16:25 | +2.6° |
| （参考・EXP-016記録の「16:30」） | 16:30 | +1.6° |
| **sunset（現行）** | **17:40** | **−12.1°** |
| night | 21:00 | −52.1° |

- **sunset プリセットの 17:40 は、日没（約16:38）から1時間後の薄明末期で、太陽は地平線下 −12.1°。直射光は存在しない。**
- EXP-016 の記録が根拠にした太陽高度「16:30で約+1.5°」と、プリセットが符号化している 17:40 の間に **70分のずれ**があり、これまで誰も照合していなかった。プリセット表は姉妹protoから逐語継承されたもの（proto src/main.ts の TIMES と完全一致）。

## 仮説ランキング

### H1（症状Aの主因・最有力）: プリセット時刻が日没後で、PBRの磁器を照らす太陽が存在しない
- 根拠1（計算）: 上表。17:40 の空は薄明の残光のみで、拡散反射の光量は昼の数百分の一のオーダー。
- 根拠2（光量予算の内部対照）: night プリセットは太陽 −52.1°（完全な夜）でも作品として読めるが、それは ambient 0.6（sunset の4倍）+ 露出 1.7 + lift の emissive が予算を肩代わりしているから。**sunset は3プリセット中、建物への光量予算が最小**（ambient 0.15 / 露出 1.05 / emissive 0）でありながら、地面だけは lit:false + 昼焼き写真 × 暖色ティントで明るく保たれる。この非対称が「写真は読めるのに建物だけ濃紺」の観測と正確に一致する。シルエットの色味（濃紺）も、残る唯一の光源である ambient の色 0x93a7cc（青灰）と一致する。
- 根拠3（姉妹アプリとの差分）: AWAKENING は **同一の時刻 17:40・同一の ambient 0.15・同一の photoreal シーン** で成立しているが、その被写体は emissive 駆動（高さグラデーション、intensity 0.55〜1.2 + 波面 ×4、選択的ブルーム）で、太陽光の拡散反射には一切依存していない（proto src/awakening.ts）。つまり姉妹側で「直った」のは地面の暗さ（3レバー）であって、**無発光の白モデルが 17:40 に読めることは姉妹側でも一度も成立していない**。CCL の2作品は「17:40 に無発光の磁器を被写体にする」という、姉妹側が踏んでいない条件を踏んだ。
- 根拠4: EXP-022 で水位分岐が無関係だったこと（w0.6 で全棟暗い）、EXP-021 で潮≈0 のフレーム（被写体=写真地面）だけが「成立して見えた」こと、どちらも H1 で説明できる。

### H2（症状Bの主因・有力）: 体積雲＋ヘイズが、薄明の暗い空の下で黒い遮蔽になる
- 根拠: EXP-021 の A/B で、雲オフ版は 8s 時点で black 100% にならず（mean 0.199 の濁った面）、雲が開幕の純黒の主因と実証済み。EXP-022 のレシピには `clouds: "off"` が無く（hazeDensityScale:0 のみ）、黒がループの無関係な位相（31s/61s）で反復する様子は、漂う体積雲の遮蔽と整合する。太陽が地平線下では雲自体もほぼ黒く描かれるため、H1 の下では H2 の症状は増幅される（独立原因というより複合）。
- 補足: `hazeDensityScale` は実在するプロパティ（SDK 0.2.1 の three-default-descs に定義あり）なので EXP-016 レバー3が「無効な名前で無言で失敗」は否定できる。ただし coverage 0.45 / lightShafts は残っている。

### H3（症状Aの副次因・可能性は残る）: aerial perspective の transmittance がタイル側に効き続けている
- 支持: EXP-021 記録自身が提起。引きの画角ほど悪い傾向。
- 反証（主因ではない）: シルエットは 1050m ショットの近景棟を含め画面全体で一様に濃紺で、距離で段階的に死ぬ形ではない。距離消光が主因なら近景は残るはず。
- プロパティ名の実在は確認済み（`aerialPerspective` / `transmittance` は three-default-plugin dist 内に存在）。ただし `scene.aerialPerspective.update(...)` のハンドル経路が正しいかは文字列からは証明できない。検証ランで H1 修正後に遠景だけ死ぬ形が残れば、その時点で H3 が次手になる。

### H4（軽微な寄与）: evaluator の roughness が無視され、磁器が roughness 1.0 で描かれる
- porcelain の設計値 0.35 ではなくレイヤー均一値 1.0（完全拡散）になるため、夕景のスペキュラな艶が消え、マットで暗い読みに寄る。ただし実在の太陽光があれば単独で真っ黒にはならない。原因ではなく修正リスト行き。

### 却下した仮説
- **「カスタムスタイル経路が照明をバイパスして無照明描画になる」**: 却下。同一 style 経路が昼（太陽 +38.2°）の EXP-003/004 では陰影のある素材として評価されてきたこと、lift 分岐の emissive が加算的に効く（= color 分岐は照明付き拡散として扱われる）ことと矛盾する。
- **「影（castShadow）が建物を潰す」**: 却下。太陽高度 −12.1° では直射自体が無く、影は ambient の床より下には下げられない。

## Round 3 — コード診断（2026-11-26、コード読解のみ・変更なし）

SDK 0.2.1 の実物（worktree の node_modules: `@navaramap/three` / `three-default-plugin` / `three-default-descs` の dist と、`@takram/three-atmosphere` の src）を直接読んで裏取りした。

### 前提の再確認: EXP-016 レバー1（transmittance:false）は実際に届いている — H3 は棄却
- `AerialPerspectiveEffectDesc.onUpdateConfig`（three-default-descs/dist/index.js）は update の `aerialPerspective.transmittance` を pass インスタンスの setter へ転送し、`rawEffect.transmittance` に反映する。config への `Object.assign` が先行するので、pass 生成前に update しても失われない。→ ステージでは距離消光は実際に切れている。「ハンドル経路が違う/無言で no-op」は棄却。
- ただしこの pass はポストエフェクトであり、タイル・地形の全てに一様にかかる（MRT の深度を共有）。タイル専用の別大気・霧は存在しない（CCL は fog を追加していない）。残る `inscatter`（既定 true）は薄明の青い光を「足す」方向で、暗転の原因にはならない。
- `addDefaultPhotorealScene()` は引数なし（viewer.ts:80）→ `deferredLighting` なし、`view.lit` は true のまま forward 照明。タイルを照らすのはシーンライト3つ: Sun / SkyLightProbe / CCL の ambient。

### 疑惑1: 低太陽での上流照明 — 機構は3段で、主犯は「太陽光の物理的消滅」
1. **太陽の色=強さは大気透過率で決まり、低空ではほぼ0になる。** `SunLightDesc.requestTransmittanceTexture` が大気の透過率テクスチャを `SunDirectionalLight` に渡し、`applyColor` 既定 false のため太陽色は `getSunLightColor` = 太陽放射 × 透過率（@takram/three-atmosphere/src/getSunLightColor.ts、SunDirectionalLight.ts）で毎フレーム決まる。CCL は `scene.sun.update` で castShadow しか触っていない（viewer.ts:81）。太陽高度 −12.1°（sunset）では光線が地面と交わり透過率はコード上厳密に0（`rayRMuIntersectsGround` → `setScalar(0)`）。golden（+2.6°）でも気団量は約17（Kasten–Young）、透過率は 550nm で ~0.1、エアロゾル込み ~0.02 のオーダーしか残らない。**golden が「ほぼ効かなかった」のは当然で、戻したのは太陽ではなく2%の赤い残光だった。**
2. **幾何学: 見えている面は反太陽側。** golden の太陽方位は約248°（西南西）。shot 1/2 のカメラ heading は 320°/298°（recipes.ts の exp022 系）で、画面に映るファサードは南東〜東南東向き — 直射は原理的に届かない。届くのは屋根（受光係数 sin 2.6° ≈ 0.045）と西南の細い縁だけ。CHECK 1 の「右側の一部に金茶の面」はこの縁と整合する。
3. **残る光源はすべて弱く、床は ambient が決める。** SkyLightProbe は薄明の空の照度から SH を作る（空自体が暗い）。ambient は 0.15 × 0x93a7cc（viewer.ts:90）で、シルエットの濃紺はこの色そのもの。露出は tone mapping エフェクト側の最終倍率（viewer.ts:94、preset × ステージ1.25）で光を作らない。night が読めるのは ambient 0.6 + 露出 1.7 が床を約5倍持ち上げるためで、Round 1 の「sunset は最小予算」をコードで再確認した。真昼で読めたのも同じ式（透過率 ~1、屋根の受光 sin 38.2° ≈ 0.62、空光も強い）。
- 棄却した線: 「タイル素材がシーンライトを無視する」（night の ambient 持ち上げ・真昼の陰影・濃紺=ambient 色の一致と矛盾）。「view.lit=false で無照明化」（その場合は albedo のベージュがそのまま出るはずで観測と逆）。副次因として H4（レイヤー均一 roughness 1.0、viewer.ts の layer model）は残る: グレージング光のスペキュラ経路がないため艶で稼げないが、単独では真っ黒にしない。

### 疑惑2: 水位連動の暗転（真昼 shot 2: w2.6 mean 0.452 → w12 mean 0.222）— 全体パラメータは存在せず、被覆率で全量説明できる
- コード上、水位で変わるのは2つだけ。(1) style() の分岐（viewer.ts:146）: `measuredHeight ≤ w` の建物が磁器グラデーション（0xe8e2d4→0xf7f2e6、相対輝度 ~0.89–0.95）から一律 0x2e4d4a（同 0.275）へ**建物ごと**反転する。水位線での分割ではなく二値反転なので、水面より上に残る部分も全部暗くなる。(2) 水面プレーン（viewer.ts:186、9000×9000m、0x14424f＝輝度 0.224、opacity 0.55）が datum+w まで上がり、地面と全建物の下部を覆う。
- tick（viewer.ts:289–304）が触るのはカメラ・waterLevel・プレーン高さ・refresh() のみ。露出・霧・大気・ライトに水位連動の変更はコードに存在しない。
- 被覆率の概算（shot 2 = 1050m / pitch −40、画面比を 空 ~10% / 建物 ~50% / 地面 ~40% と仮定）: w2.6 では ≤2.6m の建物はほぼ皆無で全棟磁器。w12 では低層主体の月島・勝どきで建物ピクセルの ~70% が反転し、レンダー輝度は albedo 比 0.275/0.887 ≈ 0.31 倍（~0.50 → ~0.155）→ Δ ≈ 0.50 × 0.70 × (−0.345) ≈ −0.121。地面は写真（~0.5）からプレーン混色（0.55×0.224 + 0.45×0.5 ≈ 0.35）へ → Δ ≈ 0.40 × (−0.15) ≈ −0.060。合計 −0.18〜−0.23（≤12m のピクセル比率 60–80% で変動）。**実測 Δ = −0.230 は被覆率のみの範囲内**で、全体パラメータを持ち出す必要はない。
- 「暗い茶灰」の読みは、濃ティール（0x2e4d4a）が真昼の強い光とトーンマッピングでレンダーされた結果で、色指定自体は水位で変わっていない。

### 疑惑3: 広角 shot 1 のスレート色の空白 — 位相の異なる2つの空白
shot 1 は cameraOverride と shot 1 カメラが同一のため 1600m / heading 320 / pitch −48 で**静止**し、24s（ratio 0–0.5）続く（stage.ts、recipes.ts）。
- **空白A（ループ冒頭）= タイル未着。** ステージは probe ウォッチドッグで開始5秒で強制開始する（viewer.ts:281）が、LOD2 タイルのストリーミングは遥かに遅い（EXP-019/020 の記録）。未着の間は背景色 0x06080e（ThreeView の backgroundColor）＋地形/写真＋水面プレーンだけになる。1600m の広角は最もタイルを要し最も遅れる。w ≈ 0 の位相で起きるのが特徴。
- **空白B（shot 1 終盤 ~21.6–24s）= 疑惑2の広角版。** 水位カーブ（stage.ts:9–13）は ratio 0.45 で w=12 に達し 0.65 まで保持するので、shot 1 の最後 ~2.4s は最大水位、17s 以降も w ≥ ~8.4。低層が画面の大半を占める広角では、反転した暗色面＋暗いプレーンが「スレート色のシート」になり、磁器として残るのは高層だけで「街が見えない」読みになる。カメラは水面に接近しない（距離・pitch 固定）ので「水面のクローズアップ」ではない。
- 判別法: 空白の瞬間の probe 行の w 値（A は w≈0、B は w=12.0）と groundMean（A は写真が読める、B はプレーン色に沈む）。

### 修正候補（証拠の強さ ÷ 変更の小ささで順位付け）— 本ラウンドでは未実施
1. **太陽を大気透過から切り離す**: `scene.sun.update`（viewer.ts:81）に `applyColor: true` + 暖色 + intensity を追加（ステージ分岐内のみ）。透過率 0〜0.02 という実証済みの主因に直接対応する。方向は大気の日付から正しく来る（西南西・低空）ので、強さだけを人為に戻す。Chrome 確認: diag-golden + 本修正で shot 2 の磁器に暖/冷の二面が出て probe mean が 0.30 を明確に超えれば確定。
2. **水没建物を「暗くする」から「消す」へ**: style() 水没分岐（viewer.ts:146）を `show: false` に変える1行。水面下はプレーンが覆い、水上の磁器だけが残る。予測: w12 の shot 2 で暗色ボックス（~0.155）がプレーン混色（~0.35）に置き換わり mean は大幅に回復する。判別実験として先に「水没色を明るくする diag（0x2e4d4a → 0x6a8a84）」を測ると、Δ が albedo 比どおり縮むことで被覆率説が最終確定する。
3. **ステージ限定の ambient 持ち上げ**: 露出 ×1.25 と同じ流儀で、ステージ時のみ ambient 0.15 → ~0.35（viewer.ts:90 周辺）。床は上がるが二面の陰影は作らないので 1 の補助。単独では「平たいベージュ」止まり。
4. **開始ゲートの是正**: ウォッチドッグ 5s 固定（viewer.ts:281）を初回タイル描画の確認まで（上限つき）に変える。空白A 専用で、症状A・疑惑2 とは無関係に実施できる。
5. **golden 時刻の前倒し（15:30、太陽 ~+12°、透過率 ~0.3）**: データ変更のみで物理的に光は戻るが、薄明という狙い自体が変わり、反太陽側ファサードの問題は残る。1 が効かない場合の代替。
6. **（最終手段・非推奨）deferredLighting: true**: 大気照度でポスト照明する方式への変更だが、照明モデル全体の変更で、本診断の証拠はここを指していない。
