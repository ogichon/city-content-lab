# EXP-023 — ライブWeb路線の再試行・第1段: 夕景シルエット化の原因調査

## 対象の欠陥（EXP-021 / EXP-022 で2作品を止めた壁）
実Chromeのユーザースクショで2作品連続で観測された症状は、実は2つある。混同しないために分けて扱う。
- **症状A（シルエット化）**: 夕景設定のステージで、建物が磁器として照明されず、全棟が無照明の濃紺シルエットになる。EXP-022 では水位0.6（沈没対象がほぼ無い状態）でも全棟が暗い → 水の素材分岐は無関係で、夕景×建物の照明経路そのものが原因。
- **症状B（黒フレーム）**: 再生中に black 100% のフレームが反復する（EXP-022: 31s / 61s、ループの異なる位相で発生）。

## コード読解: 建物の色と照明はどう作られるか（src/viewer.ts、src/recipes.ts）
- 太陽と空は `ThreeView({ atmosphere: { date: new Date(time.iso) } })` + `plugin.addDefaultPhotorealScene()`（takram系の物理大気）。太陽位置はプリセットの絶対時刻だけで決まる。`scene.sun` は castShadow のみ上書き。
- 建物は 3D Tiles レイヤー。レイヤーレベルの model は `color: 白 / metalness: 0 / roughness: 1`（growth / standard モード）。viewer.ts のコメントどおり Navara 0.2.1 では metalness/roughness はモデル均一値が正で、**FeatureEvaluator が返す per-feature の metalness/roughness は効かない**。
- FeatureEvaluator の style コールバックが返す color / emissive / emissiveIntensity / opacity / show が特徴ごとの見えを決める。color は特徴の拡散色差し替えで、照明（PBR）自体は残る（後述の反証参照）。
- 失敗した2作品の style はどちらも **emissive = 0**:
  - EXP-021（growth 既定分岐）: `emissive: 0`（emissive を持つのは lift モードだけ: 白 × 0.15）。
  - EXP-022（porcelain 分岐）: MATERIALS.porcelain は emissive [0x000000, 0x000000] / intensity 0。
- 環境光は単一 ambient（色 0x93a7cc=青灰）のみ。プリセット強度は day 0 / **sunset 0.15** / night 0.6。
- EXP-016 のステージグレード3点（地形 lit:false / aerialPerspective transmittance:false / 雲 hazeDensityScale:0）は全て「地面」と「距離減光」への対策で、**建物に光を足すものは1つもない**。露出は stage で ×1.25 のみ。

## 実測（机上計算で確定）: プリセット時刻の太陽高度
NOAA 近似で東京（35.668, 139.778）・2026-11-05 の太陽高度を計算した。

| プリセット | 時刻 (JST) | 太陽高度 |
|---|---|---|
| day | 12:00 | **+38.2°** |
| （参考） | 16:25 | +2.6° |
| （参考・EXP-016記録の「16:30」） | 16:30 | +1.6° |
| **sunset（現行）** | **17:40** | **−12.1°** |
| night | 21:00 | −52.1° |

- **sunset プリセットの 17:40 は、日没（約16:38）から1時間後の薄明末期で、太陽は地平線下 −12.1°。直射光は存在しない。**
- EXP-016 の記録が根拠にした太陽高度「16:30で約+1.5°」と、プリセットが符号化している 17:40 の間に **70分のずれ**があり、これまで誰も照合していなかった。プリセット表は姉妹protoから逐語継承されたもの（proto src/main.ts の TIMES と完全一致）。

## 仮説ランキング

### H1（症状Aの主因・最有力）: プリセット時刻が日没後で、PBRの磁器を照らす太陽が存在しない
- 根拠1（計算）: 上表。17:40 の空は薄明の残光のみで、拡散反射の光量は昼の数百分の一のオーダー。
- 根拠2（光量予算の内部対照）: night プリセットは太陽 −52.1°（完全な夜）でも作品として読めるが、それは ambient 0.6（sunset の4倍）+ 露出 1.7 + lift の emissive が予算を肩代わりしているから。**sunset は3プリセット中、建物への光量予算が最小**（ambient 0.15 / 露出 1.05 / emissive 0）でありながら、地面だけは lit:false + 昼焼き写真 × 暖色ティントで明るく保たれる。この非対称が「写真は読めるのに建物だけ濃紺」の観測と正確に一致する。シルエットの色味（濃紺）も、残る唯一の光源である ambient の色 0x93a7cc（青灰）と一致する。
- 根拠3（姉妹アプリとの差分）: AWAKENING は **同一の時刻 17:40・同一の ambient 0.15・同一の photoreal シーン** で成立しているが、その被写体は emissive 駆動（高さグラデーション、intensity 0.55〜1.2 + 波面 ×4、選択的ブルーム）で、太陽光の拡散反射には一切依存していない（proto src/awakening.ts）。つまり姉妹側で「直った」のは地面の暗さ（3レバー）であって、**無発光の白モデルが 17:40 に読めることは姉妹側でも一度も成立していない**。CCL の2作品は「17:40 に無発光の磁器を被写体にする」という、姉妹側が踏んでいない条件を踏んだ。
- 根拠4: EXP-022 で水位分岐が無関係だったこと（w0.6 で全棟暗い）、EXP-021 で潮≈0 のフレーム（被写体=写真地面）だけが「成立して見えた」こと、どちらも H1 で説明できる。

### H2（症状Bの主因・有力）: 体積雲＋ヘイズが、薄明の暗い空の下で黒い遮蔽になる
- 根拠: EXP-021 の A/B で、雲オフ版は 8s 時点で black 100% にならず（mean 0.199 の濁った面）、雲が開幕の純黒の主因と実証済み。EXP-022 のレシピには `clouds: "off"` が無く（hazeDensityScale:0 のみ）、黒がループの無関係な位相（31s/61s）で反復する様子は、漂う体積雲の遮蔽と整合する。太陽が地平線下では雲自体もほぼ黒く描かれるため、H1 の下では H2 の症状は増幅される（独立原因というより複合）。
- 補足: `hazeDensityScale` は実在するプロパティ（SDK 0.2.1 の three-default-descs に定義あり）なので EXP-016 レバー3が「無効な名前で無言で失敗」は否定できる。ただし coverage 0.45 / lightShafts は残っている。

### H3（症状Aの副次因・可能性は残る）: aerial perspective の transmittance がタイル側に効き続けている
- 支持: EXP-021 記録自身が提起。引きの画角ほど悪い傾向。
- 反証（主因ではない）: シルエットは 1050m ショットの近景棟を含め画面全体で一様に濃紺で、距離で段階的に死ぬ形ではない。距離消光が主因なら近景は残るはず。
- プロパティ名の実在は確認済み（`aerialPerspective` / `transmittance` は three-default-plugin dist 内に存在）。ただし `scene.aerialPerspective.update(...)` のハンドル経路が正しいかは文字列からは証明できない。検証ランで H1 修正後に遠景だけ死ぬ形が残れば、その時点で H3 が次手になる。

### H4（軽微な寄与）: evaluator の roughness が無視され、磁器が roughness 1.0 で描かれる
- porcelain の設計値 0.35 ではなくレイヤー均一値 1.0（完全拡散）になるため、夕景のスペキュラな艶が消え、マットで暗い読みに寄る。ただし実在の太陽光があれば単独で真っ黒にはならない。原因ではなく修正リスト行き。

### 却下した仮説
- **「カスタムスタイル経路が照明をバイパスして無照明描画になる」**: 却下。同一 style 経路が昼（太陽 +38.2°）の EXP-003/004 では陰影のある素材として評価されてきたこと、lift 分岐の emissive が加算的に効く（= color 分岐は照明付き拡散として扱われる）ことと矛盾する。
- **「影（castShadow）が建物を潰す」**: 却下。太陽高度 −12.1° では直射自体が無く、影は ambient の床より下には下げられない。

## 机上のみで判別できたこと（本調査の実施分）
- H1 の事実核（17:40 = 太陽 −12.1°）を計算で確定。EXP-016 が前提にした 16:30（+1.6°）との70分ずれを特定。
- 「style 経路が無照明化する」仮説と「影」仮説をコード＋既存記録で却下。
- EXP-016 レバーのプロパティ名（aerialPerspective / transmittance / hazeDensityScale）が SDK 0.2.1 に実在することを、インストール済みパッケージ（姉妹protoの node_modules、同一バージョン ^0.2.1）で確認。「名前が間違っていて無言で失敗した」線は否定。

## 検証計画（最小変更＋ユーザーの実Chrome撮影1回で判別）
自己キャプチャは不可能（既知の制約）なので、判定はプローブ数値入りのスクショで行う。プローブ行（mean / black%）が写ることが数値判定の前提。

### 変更（単一変数・最小）
1. `TIMES` に `golden` を追加: sunset と tint / ambient / exposure は同一、iso のみ `2026-11-05T16:25:00+09:00`（太陽 +2.6°）に変更。**変えるのは太陽位置だけ。**
2. レシピ `exp023-diag-golden` を追加: exp022-sink-core の複製で time のみ `golden`。
3. レシピ `exp023-diag-nocloud` を追加: exp022-sink-core の複製で `performance.clouds: "off"` のみ追加（exp021-breath-nocloud と同型）。
4. 対照は既存の exp022-sink-core（無変更）。
※ 実装時の注意: public/recipes/index.json のマニフェスト再生成と、テストのピン留め件数（レシピ総数等）の追随が repo の作法として必要。

### 撮影手順（1回のセッションで全部）
各URLを実Chromeで開き、プローブが `run` になってから:
- 3レシピとも: ステージ時刻 **約20s（ショット1・引き）** と **約35s（ショット2・寄り）** で撮影（計6枚）。
- 対照（exp022）と nocloud のみ追加で: 48sループを1周見て、黒フレームが出た瞬間、無ければ約55s 時点で撮影（計2枚）。

### 予測と判定規則
| 結果 | 判定 |
|---|---|
| golden で磁器が読める（暖かい受光面＋陰影面の二面性、probe mean が対照より明確に上昇）、nocloud ではシルエットのまま | **H1 確定**。修正は sunset/golden プリセットの時刻是正（+必要なら ambient 再調整）→ EXP-022 核の瞬間を再判定へ |
| golden でも遠景だけが距離で死ぬ（近景は回復） | H3 が残存。次手は aerialPerspective ハンドル経路の実証（静止画レシピでの transmittance 有無の同条件比較） |
| golden でも全棟シルエットのまま | H1 棄却。次手は proto の plain モード（公式サンプル構成: 太陽光 intensity 2 + ambient 0.5、photoreal シーンなし）を `exp023-diag-plain` として移植し、「photoreal シーンの照明」対「データ/style」の切り分けに進む |
| nocloud で黒フレームが消え、対照では再発 | **H2 確定**（症状Bの原因）。本編レシピは雲オフを既定にする |
