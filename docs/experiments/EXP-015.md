# EXP-015 — ステージモード（Navara作品の動的化）

## PLAN
仮説: Navara作品を「自動再生される演技（カメラ振り付け＋成長/浮上/時間変化）」としてWebで演じれば、静止画では露出する弱点（LODの粗さ・昼焼き付け）が視差と動きで相対化され、Navaraならではの価値（リアルタイム・無限再生・URLで共有）が出る。ユーザー決定（2026-11-06）: 「Navaraを活かすのであれば静止画にしないほうがいい。動的コンテンツとしてみせるべき」→ 組み直しを承認。
成功条件: 既存レシピ3本（lift/growth/material）が stage URL で自動再生の演技として開ける。既存ビューアの挙動は不変。テスト全通過。

## DO
- Recipe に performance（shots列＋easing、任意で時間ドリフト、loop）を追加。
- ビューアに stage モード（URLパラメータで起動、UIを隠し __idle 後に再生、__stage で計装）。
- ギャラリーのカードから動的ピースへのリンクを追加。
- 実装は Codex（worktree）、レビューと統合は Muse。
## CHECK（2026-11-07、Muse レビュー）
- 技術: stageFrame は純関数（経過秒→カメラ）で easing／heading ラップ／loop・finished 処理が正しい。ビューア統合は ?stage= のときだけ有効化され、__idle 後に開始、growth は公演全体の progress で駆動、lift は既存の orbit/breathing を保持。既定経路の挙動は不変（手動操作の干渉ガード含む）。npm test 全通過（新規 timeline 検証含む）、npm run build 成功（ランタイム資産コピーも正常）。
- 判断材料の制約: 時間ドリフトは未実装（ビューアの時刻は初期化専用。timeFrom/timeTo は型に残し将来課題）。スカイツリーの lift レシピは repo に無いため、東京の lift レシピで代替（レシピ自体の新設は別途）。
- クリエイティブ: **未確認**（当環境では WebGL 描画を目視できない既知制約）。最終目視はユーザーの Chrome（stage URL）で行う。

## ACT
採用して公開する。目視確認後にショットの振り付け（距離・角度の弧）を調整する。
