# EXP-011 — 都市設備・地形を載せる（万博シーンの文脈拡張）

## ユーザー提案（2026-11-06）
「リングだけでなく、都市設備ものせたら？重たくなるだろうけど得るのでは」

## 調査結果
- 万博専用データセットの中身は bldg 285 + frn 985 のみ。**都市設備（CityFurniture 985点）は既に全て磁器で投入済み**だった。道路・橋梁・植生・水部といった種別はこのデータに存在しない。
- 唯一未使用だったのは DEM（TINRelief、2ファイル）。

## DO: DEM地形の変換と投入
- scripts/convert_dem.py（TIN posList をストリーム変換、都市モデルと同じ局所座標系・同じアンカー）: 47,551三角形、z範囲 −5.2〜+22.9m。埋立地でも無視できない起伏がある（島の縁、静けさの森の盛土など）。
- build_expo_scene.py に --terrain を追加: 航空写真をドレープ（UVをベースマップ範囲から生成）し、平らな写真プレーンの上に実地形が顔を出す形にした。
- 重さ: +142,653頂点 = シーン全体（553万）の約2.6%。心配された重量増はほぼ無い。

## CHECK
- 高所の全景（リビールの最終フレームと同一視点）で比較: 島の縁と盛土に陰影が出るが、1.6kmの会場に対して起伏17m程度では変化は控えめ。低角度（ヒーロー構図）では地面が「板」でなくなる効果が大きい見込み。
- 技術: 変換・ドレープとも再現可能。地形のz基準は建物（基礎 ~6.4m）と整合。

## ACT
- DEMは採用（安くて実物）。ヒーロー再描画時に地形ありで確認する。
- 本命の文脈拡張は別データ: PLATEAU大阪市（公開データ、商用可）から夢洲の隣接区画（舞洲・此花側）を変換して合体させる。リビール映像で見えた「写真の端の空白」もこれで埋まる。EXP-012として着手。
- 注意: 万博データ自体の商用禁止は合体後も万博部分に及ぶ。研究・アート用途の枠は変わらない。

## 追補（2026-11-06）: DEM変換の軸順バグと修正
v1の地形は EPSG:6697 の (lat, lon) を (lon, lat) として変換しており、座標が化けて会場外に配置されていた（NaN頂点 47,551件中の一部を含む）。高斜め比較で「変化が小さい」とした評価は、この誤配置の地形に対するものだった。convert_dem.py を修正（Triangle単位のパース＋軸順＋非有限チェック）、再生成で NaN 0件・z −5.2〜22.9m・頂点数同一を確認。修正後の地形は EXP-013 本制作で使用。
