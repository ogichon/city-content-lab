# EXP-006 — CITY LIFT（Blender切断スパイク）

仮説: Blenderで街区を切り取って浮かせる「CITY LIFT」が、実在都市モデルで成立するか。

## スパイク結果（2026-11-05、4回レンダ・全画像をClaudeが確認）
道具: scripts/blender/render_lift.py（領域内のメッシュを持ち上げ、コンクリートスラブと暗いピットを自動配置。カメラ明示指定対応）。

- v1（駅地区・既定カメラ寄せ）: 失敗。近景建物に遮られ、浮上は中央の隙間にしか見えない。
- v2（駅地区・高所カメラ）: 失敗。中央の高層に遮蔽。線路帯の見え方が支配的。
- v3（駅地区・高所85m浮上）: 機構は確認できたが、切り取ったのが線路・屋根などの平面部材中心で「瓦礫が浮く」見え方になった。**対象選定の誤り**。
- v4（八重洲側の密集市街地ブロック・70m浮上）: 部分的に成立。スラブ上の街区とピットの黒い隙間は読める。ただし周囲の高層に埋もれ、浮上感は弱い。

### 判定: 機構は実証済み、構図は未成立（条件付きGo）
- 切断・浮上・スラブ・ピットの仕組みは再現可能に動作した（スパイクの目的は達成）。
- 東京駅周辺は高層が密集し、矩形カットでは「浮く街」にならない。成立条件は (a) 周囲が低い/空間のある街区、(b) スラブとピットの対比強化、(c) 浮上高さは周辺建物との相対で決める、(d) 対象は平面インフラ（線路・屋根）ではなく容積のある市街地ブロック。
- **次の本実験は EXP-001（Navara LIFT-LITE）の知見と統合し、「LIFT × void（周囲を消して孤立させる）」で設計する。** 孤立させれば遮蔽と埋没が同時に解ける見込み。

## 再利用資産
- render_lift.py: 領域・高さ・カメラを引数化済み。対象シーンは per-object 構成のもの（駅シーン）。単一メッシュシーンでは split 版の応用が必要。

## 本実験1 — LIFT × void（2026-11-05、Muse評価済み）
EXP-001 の知見（孤立が効く）と切断を複合。八重洲ブロック（x[80,330] y[280,480]、3,639メッシュ、70m浮上、--void で周囲と地面を非表示）。

- v1（遠景）: 清潔なジオラマとして成立。ただし参照（穴・影）が無いため「浮上」は伝わらず、台座上の模型に見える。
- v2（近景+シャドウキャッチャー）: 構図は改善したが、空光では影が柔らかすぎてスラブ下に読める影が落ちなかった。見え方は v1 と同じく「標本ジオラマ」。

### 判定
- **「CITY SPECIMEN（都市標本）」フォーマットとしては成立** — 白い街区が台座ごと虚空に置かれる清潔なジオラマ。シリーズ化候補（ギャラリー候補 #3）。
- **劇的な「引き剥がされた街」としての LIFT は void では成立しない**。浮上は「下に何があるか（穴・影・地肌）」との対比でしか読めないため。
- in-context 版の残課題: (a) 周囲が開けた対象（都庁西側の公園隣接ブロック等）、(b) 単一メッシュシーンでは面分割→独立オブジェクト化してから持ち上げる工程が必要、(c) ピット内壁と地肌の質感。次期 Blender 本実験として設計する。

## in-context版 設計（2026-11-05 策定）
劇的LIFT（文脈の中で街区が浮く）の成立条件を、スパイクと void 実験の失敗から逆算して設計する。

### 対象
- 本命: スカイツリー周辺（skytree_scene.blend）の低層市街地ブロック。周囲が低く開けており、遮蔽と埋没を避けられる。タワー自体は PLATEAU 外（自作）のため切断対象に含めず、背景の文脈として残す。
- 予備: 都庁シーン西側（公園隣接）ブロック。

### 工程（単一メッシュシーン対応）
1. 面分割: 領域内の面（重心判定）を選択し、別オブジェクトへ分離する（render_lift_split.py を新設）。面粒度で切断するため境界は面の縁で切れる。
2. 浮上: 分離オブジェクトをそのまま持ち上げる。スラブは分離オブジェクトの直下に、下面も地肌マテリアルで作る。
3. ピット: 穴には内壁（4面）と底を持つ箱を沈め、地肌（暗い土色+粗さ1.0）で質感を付ける。地面プレーンとの段差で「掘られた」ことを示す。
4. 光: 太陽光を強め・低くし、スラブの影がピット内に実際に落ちるようにする（void 実験で影の不在が致命的だった）。
5. カメラ: ピットの縁と浮上体の下面が同時に見える中高度（35〜50°）から。対象の較正はヒーロー素材と同じ「分布→デバッグ色」手順。

### 成功条件
- 一目で「街区が地面から剥がれて浮いている」と読める（穴・影・地肌の3要素が画面内で確認できる）。
- 対象の実在感（スカイツリー周辺と分かる文脈）が残る。
- 評価は技術/クリエイティブ分離、ルーブリック準拠。2対象 × 2高さの4枚で判定する。

### 実装委任
- Codex へ render_lift_split.py（面分割リフター）の実装を委任する。ブリーフ: docs/briefs/codex-g-lift-split.md。

## 本実験2 — in-context LIFT（スカイツリー周辺）: 成立（2026-11-05、Muse評価済み）
設計どおり、低層市街地で文脈を残して実施。スカイツリーシーンは単一メッシュではなく per-object（BLD 37,585件）だったため render_lift.py を使用（面分割版 render_lift_split.py は都庁シーンで分離+浮上の実動作を別途確認済み、PR #20）。

- v1: 領域 x[80,340] y[-560,-330]、55m浮上、161メッシュ。浮上は読めたが、領域右端で未浮上の大規模建物とスラブが交差。
- v2（採用）: 領域 x[70,300] y[-540,-320]、70m浮上、119メッシュ、カメラを下げて (-430,-900,430)→(190,-430,5)。成果物: output/blender/exp006-lift-skytree-v2.png

### 評価
- 技術: 切断境界はクリーン（交差解消）。ピット（黒）、スラブ側面、浮上体の下面が同時に見える。描画不具合なし。
- クリエイティブ: **成功条件を満たした**。タワー足元の街区が剥がれて浮いていることが一目で読め、スカイツリーが場所の文脈を与える。**ギャラリー採用候補 #4**（最終判断はユーザー）。
- 学び: in-context LIFT の要点は (1) 低層で開けた対象、(2) 下面とピットが見える低めのカメラ、(3) ランドマークを背景に残す、の3点。浮上高さは周辺（低層なら55〜70m）との相対で決まる。

## 本実験3 — LIFT v3 ベースマップ版（2026-11-05、Muse評価済み）
ユーザーの指摘（「ベースマップが表示されていない」）を受け、地理院航空写真を EPSG:6677 ジオレファレンスで stitch（scripts/make_basemap.py、タワー実位置アンカーで照合、隅田川が建物のない帯と一致して検証）し、淡色化して地面に敷いた。render_lift.py に --basemap / --basemap-extent を追加（ピット板の上面 z=0.8 より下の z=0.05 に置くため穴は暗いまま）。
- v3（領域・カメラは v2 と同一）: 周囲の街路が建物の隙間に見え、実在感が増した。ピットは完全に暗いまま。構図の強さは v2 と同等で、地続き感が上乗せされた版として候補 #4 を v3 に差し替えた。
